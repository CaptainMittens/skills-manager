### 2. The 7-attempt drag-offset bug (the saga)

Symptom: dragged card offset from cursor; preset chips only highlighted when cursor pushed far past them.

Failed fixes (kept in history — each was a real, separately-valid change OR a learning step):

| Commit    | Fix                                       | Why it failed                                                    |
| --------- | ----------------------------------------- | ---------------------------------------------------------------- |
| `74dff52` | CSS `zoom` → root `font-size`             | Real bug, but red herring (user was at Default 1.0x)             |
| `a00c23e` | `MeasuringStrategy.Always`                | Actively harmful — latched wrong rect early                      |
| `4639ac9` | Add `DragOverlay`                         | Fixed clipping, not offset                                       |
| `d2e4522` | Portal DragOverlay → `document.body`      | Not a containing-block issue                                     |
| `12d8477` | `snapCenterToCursor` + @dnd-kit probe     | Masks symptom, broke grab point; **probe was the turning point** |
| `5e6a1ca` | Remove measuring=Always + snap            | Correct cleanup, not the cure                                    |
| `ba429f0` | `dragOverlay` measuring `ignoreTransform` | Plausible but not it                                             |

**True root cause (`130234e`):** the @dnd-kit-internal probe proved the rects were ALWAYS correct (initial rect = real card position; delta correct; overlay tracked the grab-point correctly). The actual bug was `collisionDetection={closestCenter}` resolving the drop target by the 385px card's geometric **center**, not the pointer — so with a grip-handle grab ~293px off-center, chips only highlit when the card-center (not cursor) reached them. **Fix: custom `collisionDetectionStrategy` = `pointerWithin` → `rectIntersection` → `closestCenter` fallback** (pointer-accurate for chips, sortable-safe for reorder).
